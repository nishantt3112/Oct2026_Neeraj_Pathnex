			- kubectl uncordon nodeip after marking the node schedulabe so that it can come in ready status and workload can be again deployed

		- keda vs metricsserver
			- metrics-server is a resource which is a third party software which basically collects the metrics  related to cpu and memory of a node and pod from the api server and these metrics are simply exposed by the nodes and pods on an endpoint and there is a CAdvisor who actually collects the metrics and exposes them and then the kubelet post these metrics to the kube-api server and metrics server basically collects these metrics in real time 
			- now comes the HPA so it is horizontal pod autoscaler means it is the k8s native resource which scale in and scale outs the pods on the basis of resourceutilization threshold 
			- so HPA collects the metrics from metrics server and it monitors the deployment and its avgresource utilization of cpu/mem and if required it adjust the number of pods 

			- keda 
				- kuberntes event driven autoscaler 
				- means it can reads the events from different sources which we configure like cicd related metrics messaging tools related metrics database related metrics etc etc and then there is a HPA which will scale in out the number of pods to serve the traffic properly
